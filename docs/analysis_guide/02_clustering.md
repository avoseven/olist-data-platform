[ADR 009](../decisions/009_clustering_preprocessing.md)、[ADR 010](../decisions/010_rule_flags_and_clustering_scope.md)、[ADR 011](../decisions/011_segmentation_purpose_and_roles.md) の背景、
[notebooks/03_clustering.ipynb](../../notebooks/03_clustering.ipynb)、[notebooks/04_clustering_after_flags.ipynb](../../notebooks/04_clustering_after_flags.ipynb) を見る。

K-means を 2 回試し、最終的に**クラスタリングを使わずにルールで分ける**と決めるまでの章。このプロジェクトで最も大きな方針転換で、理由を説明できるようにしておきたい部分。

## K-means の仕組み (この章に必要な分だけ)

```
1. クラスタの中心を k 個、適当に置く
2. 各顧客を、いちばん近い中心のクラスタに入れる
3. 各クラスタの中心を、入った顧客の平均の位置に動かす
4. 2〜3 を、変わらなくなるまで繰り返す
```

ここから、次の性質が出てくる。

| 性質 | 影響 |
|---|---|
| 距離で分ける | 値の大きさ (単位) がそろっていないと、値の大きい特徴量だけが効く → 標準化が必要 |
| NULL を扱えない | NULL のある顧客を外すか、埋める必要がある |
| 最初の中心の置き方で結果が変わる | 何度か試して、最も良い結果を取る (`n_init`) |
| 必ず k 個に分ける | 塊がないデータでも、k 個に区切ってしまう |

最後の性質が、この章の結論に関わる。

## 前処理 (ADR 009)

### NULL: 学習から外す

8 つの特徴量のどれかが NULL の顧客は 613 人 (0.66%)。ほかの方法と比べて、学習から外すことにした。

| 方法 | 気になる点 |
|---|---|
| **外す (採用)** | 0.66% が使われない |
| 補完し、「NULL だったか」のフラグを足す | フラグの 99.3% が同じ値になり、標準化すると NULL の顧客が極端に強調される |
| 中央値で補完するだけ | レビューがない顧客は遅延が多い (第 1 章)。平均的な顧客として扱うと歪む |

### 対数変換と標準化

```python
transformed[LOG_FEATURES] = np.log1p(transformed[LOG_FEATURES])  # 金額・注文数・商品数
Z = (transformed - transformed.mean()) / transformed.std(ddof=0)  # 標準化
```

- **標準化**: 各列から平均を引き、標準偏差で割る。どの列も平均 0・標準偏差 1 になり、単位 (レアル、日、件) の違いがなくなる。
- **対数変換** (`log1p` = log(1 + x)): 右に偏った列の、大きな値どうしの差を縮める。1 回と 2 回の差は残り、10 回と 15 回の差は小さくなる。`log1p` を使うのは、0 があっても計算できるようにするため。

対数変換しないと、注文数 15 回の顧客は平均から何十標準偏差も離れ、その数人だけでクラスタができやすい。

前処理は notebook で行い、`customer_features` には加工前の値を残す。対数や標準化は手法に依存する加工で、mart は「顧客の特徴量」を手法に依存せずに持つ層だから ([ADR 002](../decisions/002_layer_architecture.md) の層の責務)。加工前の値は、クラスタの解釈 (平均や中央値を比べる) にもそのまま使える。

## 1 回目: 8 つの特徴量で K-means (notebook 03)

### クラスタ数の評価

k = 2〜8 で試し、3 つの指標を見ている。

| 指標 | 意味 | 見方 |
|---|---|---|
| `inertia` | 各顧客と中心の距離の二乗和 | 小さいほどまとまっている。k を増やすと必ず減るので、減り方が急に緩やかになる点 (エルボー) を探す |
| シルエット係数 | 自分のクラスタとの近さと、隣のクラスタとの遠さの比較 (−1〜1) | 大きいほど、クラスタどうしが分かれている |
| ARI (調整ランド指数) | 2 つの分け方がどれだけ一致するか | 乱数のシードを変えて比べ、1 に近ければ結果が安定している |

```python
for k in K_RANGE:
    runs = [KMeans(n_clusters=k, n_init=N_INIT, random_state=seed).fit(Z) for seed in SEEDS]
    best = runs[0]
    rows.append({
        "k": k,
        "inertia": best.inertia_,
        "silhouette": silhouette_score(Z, best.labels_, sample_size=20_000, random_state=0),
        "ari_min": min(adjusted_rand_score(best.labels_, run.labels_) for run in runs[1:]),
    })
```

- `n_init`: 最初の中心の置き方を何通り試すか。`n_init=10` ではシードによって inertia が変わった (局所解で止まった) ため、50 に増やしている。**手法の設定が足りているかを先に確かめている**点に注目。
- `silhouette_score(..., sample_size=20_000)`: シルエット係数は全員どうしの距離を使うため計算が重い。2 万人を無作為に選んで計算している。

結果: inertia にはっきりした折れ曲がりがない。シルエット係数は k = 3 が最も高い (0.43)。ARI はどの k でもほぼ 1 で、安定している。

**指標だけ見れば k = 3 が良い**。しかし、ここで止めずに、中身を確かめている。

### 何で分かれたか: クラスタの中身を見る

クラスタごとに、**加工前の値**の平均を並べる (k = 3)。

| クラスタ | 人数 | 金額の平均 | 注文数 | レビュー | 遅延の割合 |
|---|---:|---:|---:|---:|---:|
| 0 | 83,673 (90%) | 135 | 1.00 | 4.29 | 0.00 |
| 1 | 6,051 (6.5%) | 151 | 1.00 | 2.26 | **1.00** |
| 2 | 3,021 (3.3%) | 289 | **2.03** | 4.13 | 0.05 |

k = 3 は「遅れを経験した顧客」と「複数回購入した顧客」が、残りから切り出されただけ。k を増やしても、それまでのクラスタはほとんど変わらず、コメントの有無 → カードの利用 → 複数商品、と 1 つずつ切り出されていく。

### 何で分かれたか: R²

特徴量ごとに、「ばらつきのうち、クラスタの違いで説明できる割合」(R²) を計算している。

```python
def r_squared(k):
    within = Z.groupby(labels[k]).transform(lambda s: s - s.mean()).pow(2).sum()  # クラスタ内のばらつき
    total = Z.pow(2).sum()                                                       # 全体のばらつき
    return 1 - within / total
```

- `groupby(...).transform(lambda s: s - s.mean())`: 各顧客の値から、その顧客のクラスタの平均を引く。`transform` は `agg` と違い、行の数を変えずに元の形で返す。
- R² が 1 に近い: その特徴量は、クラスタごとにはっきり値が違う (分割に効いている)。0 に近い: どのクラスタでも同じような値 (効いていない)。

| 特徴量 | k = 3 | k = 6 |
|---|---:|---:|
| `late_delivery_ratio` | 0.98 | 0.98 |
| `order_count` | 0.86 | 0.94 |
| `credit_card_order_ratio` | 0.00 | 0.84 |
| `total_items_amount` | **0.03** | **0.06** |
| `days_since_last_purchase` | **0.00** | **0.00** |

**金額と最近性 (RFM の 2 つ) が、まったく効いていない**。

### なぜこうなったか

第 1 章の申し送りどおりのことが起きた。93% が 0 の `late_delivery_ratio` は、標準化すると 0 が −0.27、1 が +3.75 になる。まれな値ほど平均から遠くなるので、距離はまれな 0 / 1 の違いに強く左右される。K-means は、まれな値を持つ顧客から順に切り出していた。

シルエット係数が高かったのも、まれな値の顧客が、ほかとはっきり離れていたから。**統計的に分かれていることと、顧客像として意味があることは別**。

## 2 回目: フラグで分けてからクラスタリング (ADR 010、notebook 04)

1 回目の結果を、「K-means の精度の問題」ではなく「**条件で直接判定できる特性と、データから探したい特性が、同じ入力に混ざっていた**」問題だと捉え直した。

```
全顧客 93,358 人
  ├─ リピーター (order_count >= 2)       → フラグで説明する
  ├─ 遅延経験者 (late_delivery_ratio > 0) → フラグで説明する
  └─ どちらでもない 83,901 人 (NULL を除く) → 連続値でクラスタリング
         試行 1: 金額 (log1p)、最近性
         試行 2: 試行 1 ＋ レビュー
```

リピーターかどうか、遅れを経験したかどうかは、条件を 1 行書けば判定でき、業務上の意味もはっきりしている。**ルールで説明できる違いを、K-means に探させる必要はない**。

```python
assert flagged.sum() == 8_996
assert target.sum() == 84_354
assert is_train.sum() == 83_901
```

notebook の中で、ADR に書いた人数と一致することを `assert` で確かめている。人数を絞る処理は間違えやすいので、**期待する数を先に書いておき、合わなければ止まる**ようにする。

- `8_996` は整数の `8996` と同じ。数字の間の `_` は桁の区切りで、値は変わらず、読みやすくなるだけ (`8,996` のカンマにあたる。Python ではカンマが別の意味になるため `_` を使う)。
- `flagged.sum()`: True を 1 として足すので、当てはまる人数になる。
- `assert 条件`: 条件が False なら `AssertionError` で止まる。Python を `-O` 付きで動かすと無視されるため、本番のプログラムで必ず止めたい確認には `if ...: raise ValueError(...)` を使う。

### クラスタリングの前に、分布を見る

notebook 04 では、K-means の前に、金額と最近性の 2 次元の分布を描いている。はっきり分かれた塊 (山) がいくつかあれば、K-means はそれを見つけられる。なだらかに広がっているだけなら、K-means は連続した分布を区切るだけになる。

結果: 金額は山が 1 つ、最近性もなだらかで、2 次元で見ても塊はなかった。

### 結果

| 試行 | 分かれ方 |
|---|---|
| 1 (金額・最近性) | k = 4 で「金額が小さい / 大きい」×「最近 / 以前」の 4 つにほぼ均等に分かれた。シルエット係数は k によらずほぼ同じ (0.34〜0.36) |
| 2 (＋レビュー) | レビューの低いクラスタが 1 つでき、残りは試行 1 と同じく金額と最近性で分かれた |

試行 2 の、レビューの値とクラスタのクロス集計 (k = 4):

```python
pd.crosstab(labels[("trial2", 4)], train_raw["avg_review_score"], margins=True)
```

| クラスタ | 1 | 2 | 3 | 4 | 5 |
|---|---:|---:|---:|---:|---:|
| 0〜2 | 0 | 7 | 3,178 | 17,241 | 52,093 |
| 3 (低評価) | 5,556 | 2,217 | 3,609 | 0 | 0 |

境目は、ほぼ「レビューが 3 以下か」で決まっていた。

`pd.crosstab` は、2 つの列の値の組み合わせごとに人数を数える (クロス集計)。クラスタが何で決まっているかを確かめるのに便利。

## 方針転換 (ADR 011 の背景)

2 回の試行から、次のように判断した。

- 塊がないので、K-means は**自然な顧客群を見つけたのではなく、連続した分布を区切った**。
- 得られたクラスタは「金額が高い / 低い」「最近 / 以前」「レビューが高い / 低い」の組み合わせで説明できる。**K-means でなくても、ルールで作れる分け方**だった。
- それなら、説明しやすいルールで分けた方がよい。

この結論は「K-means が失敗した」ではない。**K-means を試したことで、このデータには自然な顧客群がないことが分かった**、というのが成果。notebook 03・04 は、ルールにすると判断した根拠として残している。

## まとめ

```
前処理
  NULL     : 外す / 補完する / フラグを足す を比べて決める
  対数変換 : 右に偏った列 (金額・件数) の、大きな値どうしの差を縮める
  標準化   : 単位をそろえる。ただし 0 / 1 の列は、少数派ほど大きな値になる
  前処理は notebook で行い、mart には加工前の値を残す
K-means の評価
  inertia・シルエット係数・ARI (安定性) を見る。n_init が足りているかも確かめる
  指標が良くても、中身を見る: クラスタごとの加工前の値、R² (何で分かれたか)
1 回目: 0 / 1 の特徴量だけで分かれた (金額・最近性の R² はほぼ 0)
  → 条件で判定できる特性と、探したい特性が混ざっていた
2 回目: フラグで外して連続値だけ → 塊がなく、分布を区切っただけ
  → ルールで作れる分け方なので、ルールにする (ADR 011)
```
