# 3. セグメントの定義

[ADR 011](../decisions/011_segmentation_purpose_and_roles.md)、[ADR 012](../decisions/012_segment_definition.md)、[ADR 013](../decisions/013_repeat_customer_definition.md)、[notebooks/05_segmentation.ipynb](../../notebooks/05_segmentation.ipynb) を見る。
ルールでセグメントを作ると決めたあと、どう分けるかを決める章。

## 先に目的を決める (ADR 011)

ルールで分けるなら、条件は自由に選べる。逆に言えば、**何のために分けるのか**が決まっていないと、条件を選べない。
そこで、ルールを決める前に、目的と指標の役割を決めている。

### 目的

**顧客の購買傾向と購入体験を理解し、ビジネス上の改善機会を探る。**

| 観点 | 位置づけ |
|---|---|
| 購買傾向を理解する | 主な目的 |
| 販促の対象を選ぶ | 応用・考察 (施策の候補を示す) |
| 施策の効果を検証する | **対象外** (施策を実施したあとのデータがない) |

「やらないこと」を書いているのが大事。このデータでは施策の効果は分からないので、「施策が効く」とは言わない、と最初に決めている。

### 指標の役割を分ける

| 役割 | 指標 |
|---|---|
| **分類に使う** (購買傾向) | 購入回数 (リピーターか)、購入金額 |
| **分類したあとで比べる** (購入体験) | 配送の遅れ、配送日数、レビューの評価・有無・コメント |
| **比べるときの確認用** | 購入時期 |
| **解釈を補う** | カテゴリ、州、支払い方法、複数商品 |

なぜ遅延やレビューを、分類の条件に使わないのか。

```
遅延を条件に使った場合:
  セグメント A = 遅延あり、セグメント B = 遅延なし
  → A と B の遅延率を比べる → 100% と 0% (当たり前。分けた条件を確かめただけ)

遅延を比べる指標にした場合:
  セグメント = 金額やリピートで分ける
  → セグメントどうしの遅延率を比べる → 「高額の顧客ほど遅延が多いか」が分かる
```

**分類に使った指標で比べても、新しいことは分からない**。分類する軸と、比べる軸を分けることで、セグメントの比較が発見につながる。

### 購入時期を分類の軸にしない理由

購入時期 (最近性) は RFM の 1 つだが、分類には使わず「確認用」にしている。

- 購入体験は、購入した月によって大きく変わる。遅延率は月によって 1.2% 〜 19.0% の差がある。購入時期で分けると、セグメントの違いが「顧客の違い」ではなく「買った時期の違い」になってしまう。
- データは 2018-08-29 で終わる。最終購入からの日数が長くても、離脱したとは言えない。

購入時期は、第 4 章で「セグメントの差が、同じ時期の注文どうしでも残るか」を確かめるのに使う。

### 金額で区切るのを単発購入の顧客だけにする理由

`total_items_amount` は、リピーターにとっては複数回の購入の合計。単発購入の顧客の 1 回の金額とは意味が違う。同じ閾値で区切ると、「回数の違い」が「金額の違い」に見えてしまう。

**同じ列でも、顧客によって意味が違うことがある**。区切る前に、その列が全員にとって同じ意味かを確かめる。

## 区切り方を決める (ADR 012、notebook 05)

単発購入の顧客を金額で区切る。区切り方の候補を並べて、比べている。

| 候補 | 境界 | 区分の数 |
|---|---|---:|
| 中央値 | 86.96 | 2 |
| 三分位 | 56.99 / 122.99 | 3 |
| 四分位 | 45.90 / 86.96 / 149.90 | 4 |
| K-means の境界 | 56.2 / 184.0 | 3 |
| 切りのよい値 | 50 / 150 | 3 |
| 切りのよい値 | 50 / 100 / 200 | 4 |

### 自然な境目があるかを確かめる

候補ごとの顧客像を比べるのに加えて、**金額を 20 等分して、指標の変化をグラフにしている**。特定の金額で指標が急に変わる (段差がある) なら、そこが自然な境目になる。

結果: どの指標も、金額が大きいほど同じ向きに、なめらかに変わった (遅延率 約 6% → 約 8%、配送日数 約 11.5 日 → 約 13.7 日、複数商品の割合 約 4% → 約 19〜21% など)。段差はなかった。区切り方を変えても、見える傾向はほとんど変わらない。

### 補足: なめらかでない形だった場合

今回は単純な形だったが、ほかのデータではよく違う形になる。「自然な境目」とは、**金額と指標の関係が、そこで変わる点**のこと。関係の変わり方で、境目の置き方が変わる。

| 形 | 関係の変わり方 | 境目の置き方 |
|---|---|---|
| なめらかに単調 (今回) | どこでも同じ | 自然な境目はない → 説明しやすい値で区切る |
| 段差 | ある金額で急に変わる | 段差の位置 |
| 単調だが傾きが変わる (折れ曲がり) | ある金額から、変わり方が急になる / 止まる | 折れ曲がりの位置 |
| 山型・谷型 | 途中で向きが逆になる | 山 (谷) の部分を独立した区分にする |

**折れ曲がり**の例: 配送日数が 150 までは横ばいで、150 を超えると急に伸びる。

```
配送日数
  │                    ／
  │                  ／
  │________________／
  └──────────────┴──────── 金額
                150
```

150 は意味のある境目になり、「150 未満では金額によらず同じ、150 以上で悪化する」と説明できる。区分の数も、折れ曲がりの数で決まる。

**山型・谷型**の例: レビューが中くらいの金額で最も低く、安くても高くても高い。この場合、「金額が大きいほど〜」という 1 文では表せない。低 / 中 / 高 に分け、中を谷の区分にする。
注意点として、**境目が谷の真ん中を通ると、谷が消える**。区分の中で平均を取るため、谷が両側の区分に半分ずつ混ざって薄まる。区切ったあとの表だけでは気づけないので、区切る前に細かく分けたグラフ (今回の 20 等分) を見る。

#### 形を見つけたら確かめること

1. **本物か (偶然の揺れではないか)**: 20 等分なら 1 区分 約 4,500 人。遅延率のような数 % の指標は、隣の区分と上下する程度には揺れる (notebook 05 でも、遅延率と低評価率に揺れがあった)。区分の数を変えても (10 等分、40 等分) 同じ形が出るか、各区分の信頼区間 (第 5 章) より山や折れ曲がりが大きいか、時期を分けても同じ形が出るかを見る。
2. **横軸の取り方で、形が変わっていないか**: 人数をそろえた 20 等分では、横軸は金額ではなく「金額の順位」になる。境目の金額を決めるときは、金額の軸 (偏りが大きければ対数の軸) でも描いて確かめる。
3. **金額そのものの影響か、ほかの要因か**: 金額が大きいほど複数商品の割合も上がる。ある価格帯に大型商品 (家具など) が集中していれば、そこだけ配送日数が山になる。カテゴリ別・商品数別に分けて描くと区別できる。
4. **業務のルールで説明できるか**: 段差や折れ曲がりは、送料無料になる金額、分割払いができる金額、一定の大きさを超えると配送方法が変わる、などの業務のルールで起きることが多い。理由が分かった境目は業務上の意味を持ち、最も説明しやすい。

#### 指標によって形が違う場合

- **目的にとって主な指標で境目を決め**、ほかの指標は区分ごとの値として比べる。全部の指標に合う区切りを無理に探さない。
- 区切ると情報が消える形なら、区切らずに、金額と指標の関係のグラフそのものを結果として示す方が正確なこともある。セグメントは説明のための道具。
- 境目の候補を機械的に探す方法 (変化点の検出、深さ 1〜2 の決定木で分割点を出す、など) もある。ただし、出てきた境目にも上の 1〜4 の確認が要る。

### 自然な境目がないなら、説明しやすさで選ぶ

| セグメント | 条件 |
|---|---|
| `repeat` | リピーター |
| `single_high` | 単発購入、150 以上 |
| `single_mid` | 単発購入、50 以上 150 未満 |
| `single_low` | 単発購入、50 未満 |

- 50 と 150 は切りのよい値で、150 は単発購入の顧客の 75% 点とほぼ同じ (ADR 012 の時点で 149.90)。「上位 約 25%」と説明できる。
- K-means の境界 (56.2 / 184.0) は、切りのよい値でなく、自然な境目である根拠もない。
- 三分位は人数がそろうが、境界が説明しにくい。

セグメントを割り当てるコード:

```python
conditions = [
    data["is_repeat_customer"],
    data["total_items_amount"] >= 150,
    data["total_items_amount"] >= 50,
]
segment = np.select(conditions, ["repeat", "single_high", "single_mid"], default="single_low")
```

`np.select` は、条件を上から順に見て、最初に True になった条件の値を返す (SQL の `case when` と同じ)。上から順に見るので、2 つ目の条件に「リピーターでない」を書かなくても、リピーターは 1 つ目で先に決まる。

## 定義を見直す (ADR 013)

ADR 012 では、リピーターを `order_count >= 2` (注文が 2 件以上) としていた。第 5 章の再購入の分析を進める中で、この定義の問題が見つかった。

- `order_count >= 2` の 2,801 人のうち **786 人は、すべての注文が初回と同じ日**だった。
- 同じ日の注文の間隔は、75% 以上が**数秒以内**。1 回の買い物が、出品者ごとに複数の注文に分かれたものと考えられる。

これらの顧客は「改めて買いに来た」とは言えない。そこで、リピーターを「**異なる購入日が 2 つ以上**」(`purchase_day_count >= 2`) に変えた。

| | 変更前 | 変更後 |
|---|---|---|
| 定義 | `order_count >= 2` | `purchase_day_count >= 2` |
| リピーターの人数 | 2,801 | 2,015 |

あわせて、次のことをしている。

- **定義を mart に移した**。リピーターの判定は複数の notebook で使うため、notebook ごとに書くと定義がずれるおそれがある。`purchase_day_count` と `is_repeat_customer` を `customer_features` に追加し、dbt のテストも足した (dbt ガイドの第 4・5 章)。
- **変更前の結果が変わるかを確かめた**。notebook 05・06 を新しい定義で実行し直し、主な結果 (リピーターの注文の遅延率が最も低い) が変わらないことを確認した。
- **ADR 012 は書き換えず、ADR 013 を足した**。012 には「リピーターの定義は 013 で置き換え」とだけ書いている。

「注文が 2 件以上 = リピーター」は自然に見える定義だが、データを詳しく見ると、業務上の意味と合っていなかった。**定義は、それを使って何を言いたいか (ここでは「改めて買いに来た」) と照らし合わせて確かめる**。

## まとめ

```
ルールを決める前に、目的を決める (やらないことも書く)
指標の役割を分ける
  分類に使う指標 と 分類したあとで比べる指標 を分ける
  → 分類に使った指標で比べても、条件を確かめるだけで発見にならない
  時期のように、結果を歪める指標は「確認用」にする
同じ列でも、顧客によって意味が違わないかを確かめる (リピーターの合計金額)
区切り方
  候補を並べて比べる。細かく区切って (20 等分) 自然な境目があるかを見る
  境目がなければ、説明しやすさで選ぶ
  段差・折れ曲がりはその位置、山・谷はその部分を区分にする (谷の真ん中で切らない)
  形が本物か (揺れ、横軸、ほかの要因) を確かめ、業務のルールで説明できるかを考える
定義の見直し
  使ってみて意味と合わなければ直す。共通の定義は mart に置く
  直したら、それまでの結果が変わるかを確かめる。ADR は足して残す
```

## 確認の問い

- 遅延の有無を、セグメントの条件にしなかったのはなぜか。
- 金額の区切りに 50 と 150 を選んだ理由を、「自然な境目」という言葉を使って説明できるか。
- 同じ日に複数の注文をした顧客を、リピーターから外したのはなぜか。
- 指標が金額に対して谷型だった場合、どう区切るか。境目を谷の真ん中に置くと何が起きるか。
