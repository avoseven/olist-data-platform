# 4. セグメント別の分析

[notebooks/06_segment_analysis.ipynb](../../notebooks/06_segment_analysis.ipynb) と、[report.md](../report.md) の 6 章を見る。
4 つのセグメントどうしで、購買の特徴と購入体験を比べる章。比べ方を間違えると逆の結論になる例が出てくる。

## 集計の単位を決める

同じ「遅延」でも、何を 1 件として数えるかで、答えられる問いが変わる。notebook 06 の冒頭で、先に整理している。

| 集計の単位 | 指標の例 | 答えられる問い |
|---|---|---|
| 顧客単位 | 遅延を 1 回以上経験した顧客の割合 | どのセグメントに遅延経験者が多いか |
| 顧客単位 | 顧客あたりの累計購入金額 | どのセグメントが売上に貢献しているか |
| 注文単位 | 注文の遅延率 | どのセグメントの注文で遅延が多いか |
| 注文単位 | 注文あたりの配送日数・レビュー | 1 回の購入の体験に違いがあるか |

### 単位を変えると、結論が逆になる

リピーターの遅延を、2 つの単位で数えた結果:

| | 顧客単位 (遅延を経験した顧客の割合) | 注文単位 (遅延した注文の割合) |
|---|---:|---:|
| `repeat` | **10.6%** (最も高い) | **5.3%** (最も低い) |

顧客単位だけ見ると「リピーターは遅延しやすい」と言いたくなる。しかし、リピーターは注文の数が多いので、遅延に遭う**機会**が多いだけ。注文 1 件あたりで見ると、リピーターの注文は最も遅延していない。

単発購入の顧客は、ほぼ 1 人 1 注文なので、どちらの単位でもほぼ同じ値になる。**1 人あたりの件数がセグメントによって違うとき**に、この差が出る。

注文単位で数えるときの注意も書いてある。リピーターの注文には同じ顧客の複数の注文が含まれるので、注文どうしは完全には独立していない。

## 分母を明示する

notebook 06 では、指標ごとに分母を書いている。

| 指標 | 分母 |
|---|---|
| `late_rate` (遅延した注文の割合) | 配達日時がある注文 |
| `review_rate` (レビューがある注文の割合) | すべての注文 |
| `review_mean` (レビューの平均) | レビューがある注文 |
| `low_review_rate` (評価が 3 以下の割合) | レビューがある注文 |

pandas の `mean()` は、NULL を自動で除いて計算する。便利だが、**何人 (何件) で計算した値なのか**が見えなくなる。分母を書いておくと、「レビューの平均」と「レビューの投稿率」を混同しなくなる。

これは [ADR 007](../decisions/007_customer_feature_principles.md) の原則 3 (NULL は除いて計算し、0 で埋めない) と、[ADR 011](../decisions/011_segmentation_purpose_and_roles.md) の「NULL の顧客は分母に入れず、計算に使った人数をあわせて示す」に対応している。

## 時期の偏りをそろえる

第 3 章のとおり、購入体験は購入した時期によって大きく変わる。セグメントによって買った時期の構成が違うと、セグメントの差に、時期の差が混ざる。

```
例: 遅延が多かった時期 (2018-03) に、single_high の顧客が多く買っていたとする
  → single_high の遅延率が高く出る
  → それは「高額の注文が遅延しやすい」のか、「遅延の多い時期に買った」のか、区別できない
```

このように、比べたい 2 つのもの (セグメントと遅延) の両方に関係して、見かけの差を作る要因を**交絡因子**と呼ぶ。ここでは購入時期が交絡因子の候補。

### 確認 1: 時期の構成を比べる

まず、セグメントごとの購入時期の構成 (四半期ごとの注文の割合) を比べる。

- 単発購入の 3 つは、構成がほぼ同じ。
- リピーターは、早い時期の割合がやや高く、最近の割合が低い (2 回目の購入には時間がかかるため)。

### 確認 2: 時期ごとに比べる

四半期 × セグメントで集計し、どの四半期でも同じ順序になるかを見る。結果: 配送日数はすべての四半期で `single_high` > `single_mid` > `single_low`。

月ごとではなく四半期にしているのは、月ごとだとリピーターの注文が少なく (月に数百件)、値が偶然大きく振れるため。

### 確認 3: 直接法による調整

各セグメントの月ごとの値を、**全注文の購入月の構成**で重み付けして平均する。「どのセグメントも、全体と同じ時期の構成で買っていたとしたら」の値になる。

**購入月の構成**とは、「全注文のうち、各月の注文が何 % を占めるか」の割合の一覧 (合計 100%)。コードの `data["purchase_month"].value_counts(normalize=True)` がこれを作っている。

#### 小さな例

月が 2 つだけで、月ごとの遅延率は、どちらのセグメントでも同じだとする。

| | 3 月 (遅延が多い) | 6 月 (遅延が少ない) |
|---|---:|---:|
| 遅延率 (X も Y も同じ) | 20% | 5% |
| X の注文の内訳 | 80% | 20% |
| Y の注文の内訳 | 20% | 80% |
| **全注文の内訳 (購入月の構成)** | **50%** | **50%** |

調整前 (各セグメント自身の内訳で平均):

- X = 0.8 × 20% ＋ 0.2 × 5% = **17%**
- Y = 0.2 × 20% ＋ 0.8 × 5% = **8%**

X の方が遅延しやすく見える。しかし、月ごとに見れば X と Y はまったく同じ。差は、X が遅延の多い 3 月に多く買っていたことだけで生まれている。

調整後 (全注文の構成 50% / 50% で平均):

- X = 0.5 × 20% ＋ 0.5 × 5% = **12.5%**
- Y = 0.5 × 20% ＋ 0.5 × 5% = **12.5%**

差が消える。つまり調整前の差は、**時期の偏りだけで生まれた見かけの差**だった、と分かる。

直接法は、もともと疫学で「年齢構成の違う地域どうしの死亡率を比べる」ために使われてきた方法 (高齢者の多い地域は死亡率が高く出る)。「比べたい集団どうしで、ある要因の構成が違うとき、共通の構成にそろえて比べ直す」と押さえておけば十分。

#### notebook 06 のコード

```python
def period_adjusted(data, metric):
    data = data[data[metric].notna()]
    weights = data["purchase_month"].value_counts(normalize=True)          # 全注文の、購入月の構成
    monthly = data.groupby(["purchase_month", "segment"])[metric].mean().unstack("segment")  # 月 × セグメントの値
    w = monthly.notna().mul(weights.reindex(monthly.index), axis=0)       # 値がある月だけの重み
    adjusted = monthly.mul(weights.reindex(monthly.index), axis=0).sum() / w.sum()
    raw = data.groupby("segment")[metric].mean()
    return pd.DataFrame({"raw": raw, "period_adjusted": adjusted})
```

- `unstack("segment")`: 縦に並んだ「月 × セグメント」を、行 = 月、列 = セグメントの表に広げる。
- `mul(weights, axis=0)`: 各行 (月) に、その月の重みを掛ける。
- `w.sum()` で割るのは、あるセグメントに注文がない月を、重みの合計から除くため。

結果 (遅延率):

| セグメント | 調整前 | 調整後 |
|---|---:|---:|
| `repeat` | 0.053 | 0.055 |
| `single_high` | 0.077 | 0.077 |
| `single_mid` | 0.069 | 0.069 |
| `single_low` | 0.061 | 0.060 |

調整の前後で、ほとんど変わらない。上の例とは逆で、**セグメントの差は、購入時期の構成の違いでは説明できない**、と言える。

一方、同じセグメントの中での時期による違い (`single_mid` の遅延率は四半期によって 3.5%〜13.1%) は、セグメントどうしの差より大きかった。ここから「購入体験への影響は、セグメントより時期の方が大きい」という解釈が出てくる。

## 事実・解釈・仮説を分ける

[ADR 011](../decisions/011_segmentation_purpose_and_roles.md) で決めたとおり、まとめを 3 つに分けている。

| 区分 | 書くこと | notebook 06 の例 |
|---|---|---|
| データから確認できた事実 | 集計の結果そのもの | 金額の大きいセグメントほど、注文の遅延率・配送日数が大きく、レビューが低い |
| 考えられる解釈 | 事実から考えられる理由。断定しない | 金額そのものではなく、商品の数や大きさ (配送の難しさ) が影響している可能性がある |
| 検証すべき施策の仮説 | 解釈が正しければ、何をすればよいか | 高額の注文で配送が悪化する要因を確かめ、梱包・配送方法を見直す |

分けて書く理由:

- **事実**は、誰が集計しても同じになる。ここが間違っていたら、集計のミス。
- **解釈**は、別の説明もありうる。例えば「リピーターの体験が良い」のは、「良い体験をしたからリピートした」のか「リピーターだから良い体験をした」のか、集計だけでは区別できない。
- **仮説**は、検証するまで効果は分からない。

混ぜて書くと、解釈が事実のように読まれる。

## まとめ

```
集計の単位を先に決める (顧客単位 / 注文単位で答えられる問いが違う)
  1 人あたりの件数がセグメントで違うと、単位によって結論が逆になる
  (リピーター: 遅延経験者の割合は最も高いが、注文の遅延率は最も低い)
分母を指標ごとに明示する (mean() は NULL を黙って除く)
時期の偏り (交絡因子) をそろえる
  1. 構成を比べる  2. 時期ごとに比べる  3. 直接法で調整する
  調整の前後で差が変わらなければ、時期の構成では説明できない
事実・解釈・仮説を分けて書く
```

## 確認の問い

- リピーターは「遅延しやすい」と言えるか。顧客単位と注文単位の両方の数字を使って説明できるか。
- 直接法による調整で、調整前と調整後の値がほとんど同じだったことは、何を意味するか。
- 「金額の大きい注文ほどレビューが低い」は、事実・解釈・仮説のどれか。「高額の商品は配送が難しいからレビューが低い」はどうか。
