# 013. リピーターの定義を「2 つ以上の異なる日に購入した顧客」にする

- 日付: 2026-11-02
- ステータス: 決定

## 背景

[012](012_segment_definition.md) では、リピーターを `order_count >= 2` (delivered の注文が 2 件以上) と定義した。

初回の購入体験とリピートの関係を調べる中で、次のことがわかった。

- `order_count >= 2` の顧客 2,801 人のうち **786 人は、すべての注文が初回と同じ日**だった。
- 同じ日に続いた注文 (890 件) の間隔は、**75% 以上が数秒以内**だった。1 回の買い物が、出品者ごとなどの理由で複数の注文に分かれたものと考えられる。

これらの顧客は「改めて買いに来た」とは言いにくい。また、2 つ目の注文は初回の注文の配送より前に行われているため、初回の購入体験の影響を受けようがない。
012 の定義のままでは、リピーターの購買行動や購入体験を誤って解釈するおそれがある。

## 決定

### 1. リピーターの定義

リピーターを、**delivered の注文がある、異なる購入日が 2 つ以上の顧客**とする。

| 項目 | 変更前 (012) | 変更後 |
|---|---|---|
| 定義 | `order_count >= 2` | `purchase_day_count >= 2` |
| リピーターの人数 | 2,801 | 2,015 |
| 同じ日に注文が分かれただけの顧客 (786 人) | リピーター | 単発購入 (同じ日の注文を合計した金額で区切る) |

セグメントの金額の区切り方 (50 と 150) は、012 のまま変えない。変更後の人数は次のとおり。

| セグメント | 条件 | 人数 | 割合 |
|---|---|---:|---:|
| `repeat` | `is_repeat_customer` | 2,015 | 2.2% |
| `single_high` | `is_repeat_customer` が FALSE かつ `total_items_amount >= 150` | 22,644 | 24.3% |
| `single_mid` | `is_repeat_customer` が FALSE かつ `50 <= total_items_amount < 150` | 41,723 | 44.7% |
| `single_low` | `is_repeat_customer` が FALSE かつ `total_items_amount < 50` | 26,976 | 28.9% |

### 2. mart に列を追加する

`customer_features` に次の 2 列を追加する。定義は [customer_features.md](../customer_features.md) を参照。

| 列 | 意味 |
|---|---|
| `order_count` (既存) | delivered の注文の数 |
| `purchase_day_count` | delivered の注文がある、異なる購入日の数 |
| `is_repeat_customer` | `purchase_day_count >= 2` |

dbt のテストで、次を確かめる。

- `purchase_day_count` が NULL でなく、1 以上
- `purchase_day_count <= order_count`
- `is_repeat_customer` が `purchase_day_count >= 2` と一致する
- `purchase_day_count` が、staging から別の書き方で再計算した値と一致する
- 顧客ごとに 1 行 (既存の `customer_unique_id` の unique テスト)

### 3. 再購入の定義 (初回の購入体験の分析)

初回の購入体験と再購入の関係を調べる分析では、次のように定義する。

- **初回購入**: 顧客の最初の購入日の注文
- **同時購入**: 初回購入日と同じ日の注文。再購入とはみなさない
- **再購入**: 初回購入日より後の日の注文
- **観察期間**: 初回購入から 90 日以内の再購入を主な指標、180 日以内を補足の指標とする。それぞれ、その期間を観察できる顧客 (初回購入日が基準日 2018-08-29 の 90 日 / 180 日以上前) に絞って計算する

`repeat` (リピーター) と「90 日以内の再購入」は、別の指標として扱う。

| 指標 | 意味 |
|---|---|
| `repeat` (セグメント) | 観察できる全期間で、再購入したことがあるか |
| 90 日以内の再購入率 | 初回購入から 90 日以内に、再購入したか |

## 理由

- **「リピーター」の意味を、実際の購買行動に合わせる。** 同じ日に注文が分かれただけの顧客は、改めて買いに来ていない。
- **定義を mart で一元管理する。** `order_count` と `purchase_day_count` は異なる情報を持ち、リピーターの判定は複数の分析で使う。notebook ごとに定義を書くと、分析によって定義がずれるおそれがある。
- **観察期間の長さは、再購入までの日数の分布から決めた。** 別の日に再購入した顧客 (2,015 人) の、初回から次の購入までの日数は、中央値 74 日、75% 点 175 日、90% 点 288 日。90 日で約半数、180 日で約 4 分の 3 の再購入を捉えられる。
- **観察期間をそろえる。** データは 2018-08-29 で終わるため、最近に初回購入した顧客は、再購入する時間が短い。単発購入の顧客には、まだ再購入の機会がなかった顧客も含まれる。

## 影響

- [012](012_segment_definition.md) のリピーターの定義を、この ADR で置き換える。金額の区切り方は 012 のまま。
- [notebooks/05_segmentation.ipynb](../../notebooks/05_segmentation.ipynb) と [06_segment_analysis.ipynb](../../notebooks/06_segment_analysis.ipynb) を、変更後の定義で実行し直した。リピーターの注文の遅延率が最も低い (5.3%) という結果は、定義を変えても変わらなかった。
- `order_count` は、注文の数として残す (`customer_features` の既存の特徴量や、注文単位の集計との突き合わせに使う)。

## 見直す条件

- 同じ日でも、時間を空けて改めて購入したと考えられる注文が多いとわかった → 日付ではなく、注文の間隔 (時間) で区切ることを検討する
- 出品者ごとの分割を直接判定できる情報 (sellers テーブルなど) を使うことにした → 判定の方法を見直す
