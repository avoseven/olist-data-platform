# 009. クラスタリングの前処理

- 日付: 2026-10-29
- ステータス: 決定

## 背景

[008](008_feature_selection.md) で、K-means に入力する特徴量を 8 つ選んだ。
クラスタリングの前に、次の 2 点を決める必要がある。

- **NULL の扱い**: K-means は NULL を扱えない。
- **値の大きさと偏りの違い**: K-means は距離で顧客を分けるため、値の大きさがそろっていないと、値の大きい特徴量が結果に強く効く。また、ごく一部の顧客だけが極端な値をとる特徴量があると、その数人だけでクラスタができることがある。

採用した 8 つの特徴量のうち、NULL がある顧客は次のとおり (全 93,358 人)。

| 特徴量 | NULL の人数 | NULL になる理由 |
|---|---:|---|
| `avg_review_score` | 604 | 採用できるレビューがない |
| `has_review_comment` | 604 | 同上 |
| `late_delivery_ratio` | 8 | 配達日時が記録されていない |
| `credit_card_order_ratio` | 1 | 支払いのレコードがない |

レビューの 2 つは同じ 604 人で、ほかの NULL とは重ならない。NULL が 1 つでもある顧客は **613 人 (約 0.66%)**。

## 決定

### NULL の扱い

**NULL が 1 つでもある顧客 (613 人) は、クラスタリングの学習から外す。**
クラスタができたあとの扱い (いちばん近いクラスタに割り当てる、「分類なし」とする、など) は、結果を見てから決める。

### 特徴量ごとの前処理

| 特徴量 | 前処理 |
|---|---|
| `total_items_amount` | 対数変換 (log1p) してから標準化 |
| `order_count` | 対数変換 (log1p) してから標準化 |
| `item_count` | 対数変換 (log1p) してから標準化 |
| `days_since_last_purchase` | 標準化 |
| `credit_card_order_ratio` | 標準化 |
| `avg_review_score` | 標準化 |
| `has_review_comment` | 0 / 1 にしてから標準化 |
| `late_delivery_ratio` | 標準化 |

- 標準化の平均と標準偏差は、学習に使う顧客 (NULL のある顧客を外したあと) から計算する。
- 前処理は notebook (Python) で行い、`customer_features` には加工前の値を残す。

## 理由

### NULL がある顧客を外す理由

ほかの方法と比べて決めた。

| 方法 | 気になる点 |
|---|---|
| **学習から外す (採用)** | 0.66% の顧客が学習に使われない |
| 値を補完し、「NULL だったか」のフラグを加える | フラグの 99.3% が同じ値になる。標準化すると、NULL の顧客が極端に強調される ([008](008_feature_selection.md) の「前処理とフラグの影響」) |
| 中央値などで補完するだけ | レビューがない顧客は、遅れを経験した割合が高いなど、ほかの顧客と傾向が異なる ([008](008_feature_selection.md))。平均的な顧客として扱うと、実態を歪める |

- 補完によって「ない値」をつくらずに、基準となる結果を作れる。
- 外れるのは 0.66% のため、全体の結果への影響は小さいと考える。

### 件数の特徴量を対数変換する理由

- `order_count` (最大 15) と `item_count` (最大 24) は、ほとんどの顧客が 1 で、右に大きく偏っている。標準化だけでは、値の大きい数人が平均から何十標準偏差も離れた値になり、その数人だけでクラスタができやすい。
- 対数変換すると、大きな値どうしの差が縮まる (例: 1 回と 2 回の差は残しつつ、10 回と 15 回の差は小さくなる)。
- `total_items_amount` と同じく正の値で右に偏っているため、同じ扱いにそろえる。

### 前処理を notebook で行う理由

- 対数変換や標準化は、クラスタリングの手法や、学習に使う顧客の範囲によって変わる。mart は「顧客の特徴量」を表すテーブルとして、手法に依存しない値を持つ ([002](002_layer_architecture.md) の層の責務)。
- 加工前の値が残っていれば、クラスタの解釈 (平均・中央値の比較) にそのまま使える。

## 影響

- クラスタリングの結果は、学習に使った 92,745 人 (93,358 − 613) についてのものになる。外した 613 人の扱いは、結果を見てから決め、記録する。
- 標準化しても、0 / 1 に近い特徴量 (`order_count`・`credit_card_order_ratio`・`has_review_comment`・`late_delivery_ratio`) の影響の偏りは解決しない。まず、この前処理だけで基準となる結果を作り、そのうえで [008](008_feature_selection.md) の「次の段階で確認すること」に沿って、フラグの影響やクラスタ数を確認する。

## 見直す条件

- 外した 613 人を割り当てたときに、特定のクラスタに偏って入る、または近いクラスタがないと判断した → 補完の方法を見直す
- 対数変換したあとも、一部の顧客だけでできたクラスタが現れる → 上限で値を切る (クリッピング) などを検討する
- 保留の `avg_card_installments` (NULL が 22.9%) を追加することにした → NULL の扱いを改めて決める (学習から外すと、顧客の 2 割以上が外れるため)
