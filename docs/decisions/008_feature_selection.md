# 008. クラスタリングに使う特徴量の選定

- 日付: 2026-10-27
- ステータス: 決定

## 背景

[007](007_customer_feature_principles.md) で、特徴量は「定義を決めてから、データを確認して採用を判断する」と決めた。
定義は [customer_features.md](../customer_features.md) で確定し、`customer_features` として実装した。

区分①〜③の 17 項目 (比較候補の 2 つを含む) について、NULL の割合、分布、特徴量どうしの関係を確認し、
K-means に入力する特徴量を選ぶ。区分④ (解釈用) は対象外。
確認の詳細は [notebooks/02_feature_selection.ipynb](../../notebooks/02_feature_selection.ipynb) を参照。

## 決定

### 採用 (8 つ)

| 観点 | 特徴量 | 理由 |
|---|---|---|
| 金額 | `total_items_amount` | 金額の代表。偏りが大きいため、対数変換して使う |
| 時期 | `order_count` | 97% が 1 だが、リピーターを捉える唯一の特徴量 |
| 時期 | `days_since_last_purchase` | 分布にばらつきがあり、ほかの特徴量との相関も弱い |
| 商品 | `item_count` | まとめ買いの傾向。`order_count` との順位相関は 0.47 で、別の情報を持つ |
| 支払い | `credit_card_order_ratio` | 支払いの行動。ほかの特徴量とほぼ無相関 |
| 体験 | `avg_review_score` | 満足度。NULL は 0.6% |
| 体験 | `has_review_comment` | 43% が TRUE でばらつきがあり、スコアとの順位相関も弱い (−0.17) |
| 体験 | `late_delivery_ratio` | 配送の体験。比較候補のうち、こちらを採用する (下記) |

### 保留

| 特徴量 | 理由 |
|---|---|
| `avg_card_installments` | 分割払いの行動として意味はあるが、NULL が 22.9% あり、金額とも順位相関 0.45 がある。最初の結果を見てから、追加するかを判断する |

### 不採用

| 特徴量 | 理由 |
|---|---|
| `avg_order_items_amount` | `total_items_amount` と順位相関 0.99 |
| `avg_item_price` | `total_items_amount` と順位相関 0.94 |
| `freight_ratio` | 金額と強い負の順位相関 (−0.78〜−0.82)。送料は価格に比例しないため、顧客の行動より商品の価格の影響が大きい |
| `days_since_first_purchase` | `days_since_last_purchase` と順位相関 0.99 |
| `distinct_category_count` | 97.7% が 1。`order_count` と順位相関 0.61 |
| `has_used_voucher` | 96.2% が FALSE |
| `avg_delivery_days` | 配送先や物流の影響が強いと考えられる。配送の体験は `late_delivery_ratio` で表す |
| `avg_delivery_delay_days` | 比較の結果、`late_delivery_ratio` を採用する |

### 配送の比較候補について

[customer_features.md](../customer_features.md) で決めた観点で比べ、`late_delivery_ratio` を採用する。

| | `avg_delivery_delay_days` | `late_delivery_ratio` |
|---|---:|---:|
| NULL の割合 | 0.0% | 0.0% |
| 最も多い値の割合 | 7.2% | 93.0% |
| `avg_review_score` との順位相関 | −0.18 | −0.31 |
| `avg_delivery_days` との順位相関 | 0.31 | 0.39 |

- 遅れを経験した顧客のレビューの平均は、すべて遅れ 2.26 / 一部遅れ 3.23 / 遅れなし 4.29 と大きく異なる。
- `avg_delivery_delay_days` は、配送予定日の設定の長さを主に表している可能性がある (遅れの中央値は −12 日)。
- `late_delivery_ratio` は「遅れを経験した顧客」と解釈しやすい。
- レビューとの相関が強いことだけを理由にはしていない。値の偏り (93% が 0) は、次の段階でフラグの影響として確認する。

## 理由 (全体)

- **似た情報を持つ特徴量は 1 つに絞る。** K-means では、似た特徴量を複数入れると、その観点がクラスタリングの結果に強く効きすぎる ([007](007_customer_feature_principles.md))。
- **ほとんどの顧客が同じ値になる特徴量は、原則として外す。** ただし、`order_count` はリピーターを捉える唯一の特徴量であるため残す。
- 金額・時期・商品・支払い・体験の 5 つの観点から、それぞれ 1〜3 個が残るようにした。

## 次の段階 (クラスタリング) で確認すること

### データの構造の影響

- 顧客の約 97% が 1 回購入であるため、K-means が購買行動というより、購入時期・金額・配送の体験などの違いで顧客を分ける可能性がある。
- クラスタができたら、実際に何の違いで分かれたかを確認し、「顧客セグメンテーションができた」とだけ結論づけない。

### 前処理とフラグの影響

- 採用する 8 つのうち、`order_count`・`credit_card_order_ratio`・`has_review_comment`・`late_delivery_ratio` は、実質的に 0 か 1 の値をとる。
- 0 / 1 の値を標準化すると、出現率の低い値ほど大きな値になる (例: 93% が 0 の `late_delivery_ratio` は、0 が約 −0.27、1 が約 +3.6 になる)。標準化だけではフラグの影響は解決しない。
- まず全特徴量を標準化しただけの基準となる結果を作り、そのうえで次を比べる。
  - 標準化の前後の値の分布
  - 各特徴量が距離に与える影響
  - フラグの重みを変えたときのクラスタの構成

### レビューの欠損の扱い

- レビューがない顧客 (604 人、約 0.65%) は、ほかの顧客と比べて、遅れを経験した割合が高く (23.8%。コメントあり 9.5%、評価のみ 4.6%)、配送日数の平均も長い (18.7 日。同 13.3 日、11.8 日)。最終購入からの日数による偏りはない。
- レビューの欠損と配送の体験には関連がある可能性があるが、因果関係は判断できない。
- 欠損がランダムではない可能性があるため、平均値などで単純に補完しない。補完の方法 (「レビューの有無」のフラグを加える、クラスタリングから外して後から割り当てる、など) は、この関連を踏まえて決める。

### クラスタ数と評価

- k = 3〜6 などで試し、次を確認する。
  - クラスタごとの顧客数と構成比
  - クラスタごとの特徴量の平均・中央値・分布
  - シルエット係数などの分離度の指標
  - 初期値を変えたときの結果の安定性
- 偏った特徴量が多いため、シルエット係数が高いことだけを理由に良い結果と判断しない。統計的な分離の良さと、顧客像として解釈できるかは別の観点として評価する。

## 影響

- [customer_features.md](../customer_features.md) に、各特徴量の採用状況を記載する。
- 不採用の特徴量も `customer_features` の列としては残す (クラスタの解釈や、見直しの際に使うため)。
- `days_since_last_purchase` は、現在の顧客の状況ではなく、データの観測期間の終わり (基準日 2018-08-29) 時点での最近性を表す。結果を解釈する際はこの点に注意する。

## 見直す条件

- 最初の結果で、特定の観点が欠けている、または特定の特徴量が強く効きすぎていると判断した → 保留・不採用の特徴量の追加や入れ替えを検討する
- フラグの影響を扱うために、K-means 以外の手法 (連続値とカテゴリ値を両方扱える手法など) を使うことにした → 特徴量の形式 (割合のまま使うか、フラグにするか) を見直す
