# 012. セグメントの定義

- 日付: 2026-10-29
- ステータス: 決定

## 背景

[011](011_segmentation_purpose_and_roles.md) で、リピーターを 1 つのセグメントにし、単発購入の顧客を `total_items_amount` で区切ると決めた。
区切り方は、候補の人数と顧客像を比べてから決めることにしていた。
比較の詳細は [notebooks/05_segmentation.ipynb](../../notebooks/05_segmentation.ipynb) を参照。

## 決定

全顧客 (93,358 人) を、次の 4 つのセグメントのどれか 1 つに割り当てる。

| セグメント | 条件 | 人数 | 割合 |
|---|---|---:|---:|
| `repeat` (リピーター) | `order_count >= 2` | 2,801 | 3.0% |
| `single_high` (単発・高額) | `order_count = 1` かつ `total_items_amount >= 150` | 22,229 | 23.8% |
| `single_mid` (単発・中額) | `order_count = 1` かつ `50 <= total_items_amount < 150` | 41,399 | 44.3% |
| `single_low` (単発・低額) | `order_count = 1` かつ `total_items_amount < 50` | 26,929 | 28.8% |

- 金額の単位は、データの通貨 (ブラジルレアル)。`total_items_amount` は商品価格の合計で、送料を含まない ([customer_features.md](../customer_features.md))。
- 境界の値は、上の区分に入る (50 ちょうどは `single_mid`、150 ちょうどは `single_high`)。
- セグメントは、当面は notebook の中で作る。

## 比べた候補

| 候補 | 単発購入の顧客の金額の境界 | 区分の数 |
|---|---|---:|
| 中央値 | 86.96 | 2 |
| K-means (対数を取った金額のみ) | 84.0 | 2 |
| 三分位 | 56.99 / 122.99 | 3 |
| K-means (対数を取った金額のみ) | 56.2 / 184.0 | 3 |
| **切りのよい値 (採用)** | **50 / 150** | **3** |
| 四分位 | 45.90 / 86.96 / 149.90 | 4 |
| 切りのよい値 | 50 / 100 / 200 | 4 |

## 理由

- **金額による自然な境目はない。** どの候補でも、金額の大きい区分ほど、購入体験・解釈用の指標が同じ向きに変わる (金額が最も小さい区分 → 最も大きい区分で、遅延率 約 6% → 約 8%、レビューが 3 以下の割合 約 20% → 約 24%、配送日数 約 11.5 日 → 約 13.7 日、複数商品の割合 約 4% → 約 18%)。特定の金額を境に、はっきり変わる段差は見られず、区切り方を変えても見える傾向はほとんど変わらない。
- **そのため、説明しやすさで選んだ。** 50 と 150 は切りのよい値で、150 は単発購入の顧客の 75% 点 (149.90) とほぼ同じ。「上位 約 25%」とも説明できる。50 は、およそ 30% 点。
- K-means の境界は、切りのよい値でなく、自然な境目である根拠もない。
- 三分位は人数がそろうが、境界 (56.99 / 122.99) が説明しにくい。
- 区分が 2 つだと、金額による違いを見る段階が少ない。4 つにすると、隣り合う区分の差がさらに小さくなる。

## 影響

- セグメント別の購入体験の分析では、[011](011_segmentation_purpose_and_roles.md) のとおり、購入時期をそろえた確認を行う。
- 金額の大きい区分ほど複数商品の割合が高い。配送日数や遅延の違いは、金額そのものではなく、商品の数や大きさなどの影響である可能性があるため、分析で確認する。
- リピーターは顧客単位で見ると注文が多いため、「遅延を経験した顧客の割合」は単発購入の顧客より高くなりやすく、複数商品の割合は定義上 100% になる。セグメントどうしを比べるときは、注文単位の指標もあわせて見る。

## 見直す条件

- セグメント別の分析で、単発購入の 3 つの区分の間に、意味のある違いがほとんど見られない → 区分の数を減らすか、別の軸を検討する
- セグメントを、ほかの分析やレポートでも使うことになった → mart の列 (またはテーブル) にすることを検討する
