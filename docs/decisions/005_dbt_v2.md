# 005. dbt v2 を使う

- 日付: 2026-10-15
- ステータス: 決定 ([003](003_transformation_tool.md) のうち、dbt Core を使うという部分を置き換える)

## 背景

[003](003_transformation_tool.md) で、変換ツールに dbt Core (v1) を使うと決めた。

環境構築の際に、dbt v2 が新規インストールの標準になっていることがわかった。
dbt v1 は引き続きサポートされているが、新しい機能は今後 v2 にのみ追加される
(dbt 公式ドキュメント「Upgrading to v2」、2026-10-08 更新)。

dbt v2 には次の 2 種類がある。

| 種類 | パッケージ | ライセンス | 内容 |
|---|---|---|---|
| 標準版 | `dbt` | dbt v2 のライセンス契約 (ローカルでの利用は無料) | オープンソース版に加え、SQL の静的解析、VS Code 拡張での補完・エラー表示、`dbt lint` を含む |
| オープンソース版 | `dbt-oss` | Apache 2.0 | 実行エンジンと標準のコマンド (`run`, `build`, `test` など) |

## 決定

**dbt v2 の標準版** (`dbt` パッケージ) を使う。uv の環境に Python パッケージとして追加して管理する。

dbt を変換ツールにするという判断 ([003](003_transformation_tool.md)) は変わらない。

## 理由

- **移行の手間がない。** 新しく作るプロジェクトのため、v1 で作ったものを移行する必要がない。
- **新しい機能は v2 にのみ追加される。** 学ぶのであれば、v2 のほうが長く役に立つ。
- **書き間違いを早い段階で検出できる。** v2 は、設定の書き間違いや存在しないマクロを解析の時点でエラーにする。v1 では、黙って無視されることがある。
- **BigQuery に正式対応している。** BigQuery は GA であり、`dbt_utils` などの定番パッケージも v2 に対応している。
- **標準版を選ぶのは、** VS Code での補完やエラー表示が dbt の学習に役立つためである。オープンソース版が必要になる理由 (Apache 2.0 のコードであることが求められるなど) は、このプロジェクトにはない。

## 検討した代替案

### dbt v1 (dbt Core)

実績が長く、解説記事や Q&A が多い。引き続きサポートされており、今回の目的も達成できる。
ただし、新しい機能が追加されないため、新しく始めるプロジェクトで選ぶ理由が弱い。

### dbt v2 のオープンソース版

Apache 2.0 のライセンスで使えるが、補完やエラー表示などの開発支援機能がない。
ライセンスの制約がないこのプロジェクトでは、標準版の利点を手放す理由がない。

## 影響

- dbt v2 は新しく、解説記事や Q&A がまだ少ない。公式ドキュメントを一次情報として参照する。
- v1 向けの記事に載っている機能の一部は、v2 では使えない (例: `--models` フラグは `--select` に置き換え)。

## 見直す条件

- BigQuery サンドボックスで、必要な機能が v2 では動かない
- 標準版のライセンス条件が変わり、このプロジェクトでの利用に支障が出る
